Privacy engineering · synthetic PoC

Data Governance & Masking

PII classification and consistent pseudonymization across synthetic relational data.

Explore the architecture ↓

Context

A personal proof of concept on synthetic relational data, focused on PII classification and consistent pseudonymization.

Problem

Masking sensitive identifiers one field at a time can break joins, constraints and cross-system consistency. Moving unprotected data into development or analytics environments increases exposure.

Goal

Inventory and classify PII columns, apply consistent pseudonyms across related relational data and check that the protected dataset retains the intended technical properties.

My responsibilities

I designed and documented the CLI workflow, classification and masking rules, protected-database checks and automated tests.

Architecture

Documented implementation

The local workflow generates synthetic data, inventories schemas and relationships, profiles and classifies fields, applies pseudonymization rules and validates the protected schemas. YAML policies are versioned; value mappings remain in memory during a batch.

Technical decisions and tradeoffs

  • Consistency across tables

    Deterministic pseudonyms use an external key, normalization and namespaces. Approved technical keys stay stable to preserve relationships: records remain linkable, so the result is pseudonymized rather than anonymous.

  • Ambiguous classifications

    Ambiguous classifications require an explicit decision before masking. Manual review adds work but avoids applying an arbitrary rule.

Technical checks

The project suite tests counts, constraints, cross-table relationships, consistency groups, schema drift and deterministic idempotence on the synthetic workload.

Results

  • Synthetic inventory

    20 source and 20 protected tables; 109 columns inventoried and classified in the reference workload.

  • Documented checks

    The repository suite checks relationships, constraints, absence of schema drift and deterministic idempotence on the synthetic dataset.

Scope and next steps

The workflow has been tested on synthetic data. Use with real data would require evaluation of classification, operational key management and monitoring; pseudonymization alone does not establish legal compliance.
